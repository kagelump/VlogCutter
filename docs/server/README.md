# Companion server

The companion server is an optional, private Linux node for the single-user VlogCutter workflow. It indexes read-only original-media mounts, owns a global content library and durable media jobs, hosts a Chrome review/admin application, and maintains one operation-synchronized replica for each adopted desktop project. The Mac remains usable when the server is offline.

Current compatibility is application `0.1.0`, sync protocol `1.0`, baseline format `1`, project schema `8`, control schema `12`, and backup format `1`. The frozen sync JSON schemas in [`docs/tasks/server/schemas`](../tasks/server/schemas/) describe protocol v1; change code and introduce a new version instead of editing those files in place.

## Ownership boundaries

The desktop project catalog remains canonical for portable project operations and local annotations. The server stores a separate local-SSD control catalog plus local-SSD project replicas. SQLite database files, WAL files, absolute mount paths, and original-media bytes are never synchronized. Synchronization exchanges bounded, versioned operations and path-free observations/manifests over authenticated HTTPS.

Original scan roots are immutable and bind-mounted read-only. Derived representations and backups use separate writable roots. The planned travel-ingest archive is a future, distinct create-only writable logical root; it does not weaken the current original-root rule.

The API contract is generated by the Rust server at `GET /api/openapi.json` and checked into [`packages/project-client/openapi.json`](../../packages/project-client/openapi.json). Product routes require a browser session or paired-device token except liveness, readiness, version, static web assets, and the bounded bootstrap exchange. The web UI is the normal human API client; `rcdvlog server ...` is the stable machine-readable surface.

## Current limits

This is single-user software, not a multi-user collaboration service. It does not upload originals, expose Tailscale Funnel, delete projects/media/representations from the web UI, perform automatic cleanup, resolve chronology conflicts in Chrome, or provide high availability. Ubuntu, Compose rendering, physical NAS behavior, LAN/Tailscale HTTPS, native Tauri pairing/playback, and target-laptop resource behavior still require the release-topology acceptance run recorded in the Task 19 report.
